# API 调用与歌曲流量

管理员面板概览与文档站的「服务用量」使用同一份公开聚合数据。统计从服务首次启用采集时开始，开始前没有历史样本。时间按北京时间（UTC+08:00）划分，周从星期一开始。

- **API 调用次数**统计进入 CurrentMusic API 后端的 GET、HEAD、POST、PUT 和 DELETE，包括返回错误的请求。排除健康探测、用量统计和上报、Nginx 静态资源、站点入口、头像与挂件。由 CDN 缓存直接响应的请求未到达后端。
- **服务端歌曲流量**统计 CurrentMusic 音频中转实际写出的响应体字节，包括投屏的 Range 响应。相同数据重新发送会再次累计。
- **直连歌曲流量**由支持上报的 CurrentMusic 播放器依据已缓冲的不重叠音频时长估算。优先使用文件大小与时长，其次使用音源码率，缺少时按 320 kbps 估算。同一音源会话复用预取数据。缓存命中、重复下载、浏览器清除缓冲等情况会带来误差。独立下载器以及未实现上报的客户端不在覆盖范围内。

公开统计只提供聚合数值。直连上报只提交随机会话标识和累计字节数，上报处理不会将账号 ID、曲目 ID 或音源地址写入统计表。

## GET /cm/usage

无需认证。响应包含 Unix 秒级时间戳 `generatedAt`、采集起点 `since`、时区 `timezone` 和 `periods`。其中 `periods` 对象有四个键。

| 键 | 当前统计周期 | 明细粒度 |
| --- | --- | --- |
| `year` | 今年 | 按月 |
| `month` | 本月 | 按日 |
| `week` | 本周 | 按日 |
| `day` | 今日 | 按小时 |

每个周期包含 `start`（起始时间）、`total`（累计值）和 `series`（按时间升序的明细）。明细对象带时间戳 `t`。累计值和明细均含整数 `apiCalls`、`servedBytes`、`directEstimatedBytes`。歌曲流量合计为后两项之和。统计周期开始之前的数据不纳入该周期。

## POST /cm/usage/audio

需要登录 Bearer。请求体为 JSON，最大 256 字节。

```json
{"session":"0123456789abcdef0123456789abcdef","bytes":1048576}
```

为每段独立音频加载生成新的 32 位小写十六进制随机标识。会话内持续上报累计估算字节，单会话上限 1 GiB。服务端按照收到上报的时间计入增量，同一会话的重复或低值上报不会重复累计。去重记录在最后一次增量上报后保留约两天。成功返回 `{"ok":true}`。
