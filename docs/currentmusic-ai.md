# CurrentMusicAI（聊天室联网问答助手）

`CurrentMusicAI` 是站内 AI 账号，不是真人。它有一个机器人头像和 **AI** 徽章，
不出现在「发现 → 用户」广场，但可以在 @ 提及选择器里搜到。

## 怎么用

1. 在「发现 → Chat」输入 `@` 选择 **CurrentMusicAI**；
2. **可以直接提问，不需要引用卡片**；如果先引用一张单曲 / 专辑 / 歌手 / 歌单卡片，
   AI 会结合卡片信息回答；追问时能理解「它 / 这首歌 / 这位歌手」的指代；
3. 输入框上方会自动出现「猜你想问」：
   - 引用卡片时按类型给出问题（创作背景 / 影视出处 / 歌手生平 等）；
   - 没有卡片时给出通用问题（最近好听的歌 / 通勤推荐 / 介绍本站）。
   点一条即可填入问题，也可以自己写；
4. 发送后，AI 会以机器人账号在聊天室里回复（SSE 实时下发）。

## 上下文

- 按用户 ID 保存最近 **6 轮**问答（有效期 7 天），不同用户互不影响；
- 追问会带着这段上下文去问模型；
- 发送「清除上下文」或 `/reset` 可清空自己的上下文；
- 快速连续追问会排队等待（不静默丢弃），同一用户同时只处理一个请求。

## 模型与联网

- 模型提供商：**深度求索（DeepSeek）**
- 模型：`deepseek-flash`
- 工具：`POST https://api.deepseek.com/v1/tools/search`（联网搜索）与
  `POST https://api.deepseek.com/v1/tools/fetch`（抓取网页正文）
- 服务端按「模型 → 工具调用 → 工具结果 → 模型」循环，最多 4 轮；
  单次请求最多搜索 3 次、抓取 1 个网页；回答约 500 字（硬上限 800，按句子边界截断）。
- **思考强度**：`reasoning_effort` 默认 `high`（该模型默认也是 high），
  可用 `CM_AI_EFFORT=low|high|max` 调整（low 更快更省，high/max 更深入）。

## 配置

密钥只从环境变量读取，**不写入仓库**：

```ini
# /etc/systemd/system/currentmusic.service.d/ai.conf  (0600)
[Service]
Environment=CM_AI_KEY=sk-...
Environment=CM_AI_MODEL=deepseek-flash
Environment=CM_AI_EFFORT=high
```

修改后 `systemctl daemon-reload && systemctl restart currentmusic`。
未配置密钥时，AI 账号会回复「AI 助手还没接入模型，请联系管理员配置 DeepSeek。」

## 频率与并发

- 同一用户两次提问最小间隔 5 秒（超出则排队等待）；
- 同时最多 2 个 AI 请求；
- 回答失败会回复「联网查询失败了，稍后再问我一次吧。」，不会静默。

## 隐私说明

用户引用的卡片信息（类型、名称、歌手/作者、ID）与问题文本会发送给 DeepSeek
及其联网检索工具；AI 的回答作为一条普通聊天消息保存在聊天室。请勿在提问中
包含敏感个人信息。


## 系统提示词

```
你是 CurrentMusicAI，CurrentMusic 音乐社区的 AI 助手。用户在聊天中向你提问。如果消息里附带「卡片信息」，请结合卡片回答；当前消息里带有卡片时以当前卡片为准，没有卡片就按问题本身回答。你可以调用 search（联网搜索）与 fetch（抓取网页）核实信息；优先用卡片或问题里的名称/歌手/专辑/作者作为搜索词。
回答要求：
- 中文，500 字以内；用纯文本，不要 Markdown 标记（不要 **、#、- 等）；
- 先给结论，再给 2~3 条要点，每条单独一行；
- 只基于卡片信息与检索到的资料，不编造；资料不足就直说；
- 如果用户在做追问，结合对话上下文理解“它/这首歌/这位歌手”指代的对象；
- 不要输出工具调用过程、搜索链接清单或“根据搜索结果”这类套话。
```
