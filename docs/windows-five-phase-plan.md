# CurrentMusic for Windows 五阶段开发计划

日期：2026-11-01。范围：在本私有全量仓库的 `windows/` 开发 C# / WinUI 3 原生 Windows 应用，复用现有 CurrentMusic HTTP API。Windows 客户端独立版本从 `0.1.0` 开始，本轮交付版本为 `1.0.0`。

## 技术与交付边界

- UI：WinUI 3 XAML、系统 Fluent 控件、系统标题栏；业务与平台 UI 分离。只读偏好保存在 `%LOCALAPPDATA%/CurrentMusic/Windows/settings.json`，凭据禁止放入该文件。
- 工具链：.NET 10 LTS、Windows SDK 10.0.26100、固定 Windows App SDK 2.6.4 稳定版。面向 Windows 10 2004（19041）及以上，x64 优先、ARM64 同步编译；Windows 11 的 Mica 等视觉增强后续按系统能力启用。
- 应用采用 unpackaged、自包含运行时，由 WiX MSI 安装到 Program Files；升级采用 MSI MajorUpgrade，提供修复和卸载。当前无代码签名证书，因此交付未签名 MSI；签名和覆盖全部实机矩阵仍不能宣称已经完成。
- 网络通过原生 HttpClient；只保存完整 HTTPS API 基址。第一阶段不接收密码或令牌，也不变更服务端协议。
- 日常交付立即提交并推送私有全量库。用户明确要求“发版”后才进行现有公开仓库及 Android 发布流程；Windows 源码公开范围、安装包渠道须另行确定，不能自动混入现有公开导出流程。
- Windows 专属实现不需要部署 Web 静态资源。本计划不修改现有 Web、Android、X 侧或后端行为。

## 第一阶段验证记录

第一阶段功能代码已交付，尚待 Windows 实机验收。2026-11-01 本地 .NET 10.0.403 检查通过 8 组（含公网探针）；[Windows CI](https://github.com/backrooms-yrc/CurrentMusic/actions/runs/41317927628) 已完成 Linux 核心检查、Windows x64 与 ARM64 核心检查和原生自包含构建，两种架构产物均已上传。实现提交为 `6c4bc88`，构建与运行说明见 `windows/README.md`。编译成功不等于 Windows 运行验收通过。

Windows 实机检查：

1. 按 README 构建并启动 x64 开发预览，确认界面由 WinUI 原生控件呈现且四个导航入口可达。
2. 调整窗口大小与 100%/150%/200% 缩放，检查窄窗导航、滚动、底部控制区与键盘焦点。
3. 切换三种主题，关闭重开，确认主题与服务地址保留；损坏偏好 JSON 后重开应回退默认值。
4. 连接默认服务；保存错误域名及非服务端 HTTPS 地址，确认错误可读、界面可继续操作；非法 HTTP/查询串地址保存失败。
5. 检测途中关闭窗口，检查无未处理异常；检测期间保存新地址，旧结果不得覆盖当前状态。
6. ARM64 构建产物在 ARM64 Windows 上启动核验。第五阶段另补干净系统与安装测试。

依据：[Microsoft Windows App SDK 稳定版下载](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/downloads)、[WinUI 3 unpackaged 部署](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/unpackage-winui-app)。版本已通过 NuGet 包目录核对，后续升级需重新验证。
