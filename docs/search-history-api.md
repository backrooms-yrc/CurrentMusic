# 搜索历史与多端同步

登录后，Web、Android WebView 和 Windows WebView 使用同一份 CurrentMusic 账号搜索历史，无需绑定网易云。同一账号各设备共享最近 10 个关键词，按最近搜索排序、去除重复，重复搜索会将关键词移到首位。

## 接口

以下接口均需 `Authorization: Bearer <CurrentMusic token>`，用户身份由当前会话确定，不接受指定其他用户。响应均带 `Cache-Control: no-store`。

| 方法 | 路径 | JSON 请求体 | 行为 |
| --- | --- | --- | --- |
| GET | `/cm/search/history` | 无 | 读取当前账号历史 |
| POST | `/cm/search/history` | `{"keyword":"周杰伦"}` | 新增或将关键词移到首位 |
| DELETE | `/cm/search/history` | `{"keyword":"周杰伦"}` | 删除单条 |
| DELETE | `/cm/search/history` | `{}` | 清空当前账号历史 |
| POST | `/cm/search/history/import` | `{"keywords":["最近搜索","较早搜索"]}` | 一次性迁移旧客户端本地历史 |

所有成功响应为 `200`：

```json
{"history":["周杰伦","七里香"]}
```

关键词需为去除首尾空白后长 1–200 字符的字符串。迁移最多接受 10 条，按从新到旧排列；重复项保留第一次。无有效会话返回 `401`；非法字段、类型或长度返回 `400`。删除不存在的关键词仍返回当前历史。

## 同步行为

- 每次明确执行搜索时立即在当前设备显示并写入云端；输入候选词时不写历史。
- 打开搜索页、窗口获得焦点、页面恢复可见和网络恢复时同步。搜索页保持打开时，每 15 秒拉取一次。
- 各设备以新增、删除、清空操作更新服务端；服务端事务串行处理并返回最新历史，避免整份本地列表覆盖其他设备的新搜索。
- 请求失败时保留本地缓存及待提交操作，下次同步时重试。云端删除会在下一次同步后反映到其他在线设备；离线期间的明确操作按重新提交的顺序处理。
- 未登录时只保留本地历史。账号缓存按 API 服务地址和用户名隔离；切换账号后忽略旧会话的迟到响应。

## 旧历史迁移

旧版 `cm.searchHistory` 没有账号归属。首次登录使用此功能时，客户端把它一次性迁移到该账号，随后移除旧全局缓存；之后的游客搜索只留在本机。其他账号不会继承这份旧缓存。

服务端每个账号只接受一次旧历史导入。新增、删除或清空云端历史后也会关闭该账号的旧历史导入，避免其他旧设备把已删除的关键词重新带回来。普通同步不会重新上传本地缓存快照。

该功能随 Web 更新部署，原生 CurrentMusicX 可按上述接口单独接入。

## 验证

后端使用临时数据库：

```bash
tools/run-tests.sh -p test_search_history.py -v
```

`tools/test-search-history.cjs` 使用两个独立浏览器上下文和临时 HTTP 服务、临时数据库，验证共享历史、并发新增、单条删除与清空、迁移、离线重试和账号切换。
