# CurrentMusic

> 一个自用的 Android 音乐播放器：Material You 界面、自建账号体系、超清母带音质，还有多人「一起听」。
> 前端是一份**没有框架的原生 JavaScript 单页应用**，跑在 Java WebView 壳里；界面用 MDUI 2（Material Design 3）。

## 音质档位

后端默认按码率择优，也可以在设置里固定档位。**各档真实规格**（取回文件头实测）：

| 档位 | 实测规格 | 码率 | 备注 |
|---|---|---|---|
| 超清母带 | 192 kHz / 24 bit / 2ch | ~5.2 Mbps | 对设备解码与重采样要求最高 |
| 臻音全景声 | 96 kHz / 24 bit / 2ch | ~3.0 Mbps | |
| 沉浸环绕声 | 44.1 kHz / 16 bit / **6ch** | ~2.3 Mbps | 杜比全景声，多声道需设备支持 |
| 高清臻音 | 上游常降级为无损 | ~1.6 Mbps | 曲库缺该档时自动回退 |
| 无损 FLAC | 44.1 kHz / 24 bit / 2ch | ~1.6 Mbps | |
| 极高 | 44.1 kHz MP3 | 320 kbps | |
| 标准 | 44.1 kHz MP3 | 128 kbps | |

> **关于「超清母带会爆音」**：把该档文件取回实测——**真峰值 -0.7 dBFS、采样峰值 -1.02 dBFS，
> 降到 48 kHz 后真峰值仍是 -0.7 dBFS**（不存在 intersample 超限），也就是说**文件本身没有削顶**。
> 出现杂音多在设备侧：192 kHz/24 bit 的实时解码加上手机音频链路的重采样跟不上，就会表现为断音/咔哒声。
> 因此播放采样率 > 48 kHz 或声道数 > 2 的档位时会提示一次，并可一键切到「无损 FLAC」。

## 常见问题

<details>
<summary><b>为什么要注册账号？不能直接用网易云账号吗？</b></summary>

播放能力由服务端的音源代理提供，账号体系是自建的（点赞/收藏/歌单/听歌统计都存在自建服务里，与上游账号相互独立）。
需要的话可以在「我的」里绑定网易云账号，用于同步红心与歌单。
</details>

<details>
<summary><b>为什么有些歌放不了？</b></summary>

地区版权限制（例如周杰伦的部分曲目对海外 IP 封锁），与会员状态无关，客户端无法绕过。遇到时会尝试备用音源，仍失败则提示不可播放。
</details>

<details>
<summary><b>提示「对设备要求较高」是什么意思？</b></summary>

说明当前档位是 192 kHz 母带或 6 声道全景声，部分机型解码/重采样跟不上会出现杂音。切到「无损 FLAC」即可（见上文[音质档位](#音质档位)）。
</details>

<details>
<summary><b>为什么没有锁屏常驻控制？</b></summary>

锁屏与耳机按键的控制走 MediaSession，已经可用；但没有做前台服务与后台常驻播放，锁屏后长时间挂后台可能被系统回收。
</details>

<details>
<summary><b>播放数据存在哪里？</b></summary>

自建服务的数据库里（点赞、收藏、歌单、听歌历史与时长统计）。网页版与 App 的数据各自独立。
</details>

## 技术实现

```
Android App（Java WebView 壳，无 androidx / 无 Gradle）
   └── 前端 SPA（原生 JS + esbuild 单包，产物直接写进 assets）
          │  HTTP + Bearer token（桥内原生请求，无 CORS 限制）
          ▼
      自建后端（Python 纯标准库 + SQLite）：账号 / 点赞 / 收藏 / 歌单 / 一起听 / 音源代理
          │
          ▼
      上游音乐 API（服务端持有凭据，客户端不接触）
```

几个值得一说的做法：

- **原生 HTTP 桥**：上游 API 不返回任何 CORS 头，WebView 里无法直接 fetch；壳内用 `HttpURLConnection`
  线程池执行并通过回调把结果交回页面，读超时放宽以兼容冷查询。
- **伪 https 源**：用 `shouldInterceptRequest` 把本地 assets 映射到一个伪 https 域，
  ES 模块、字体、localStorage 全部正常，绕开 `file://` 的各种限制。
- **歌词归一化**：上游逐字歌词是「JSON 元数据行 + `[行起始,时长](字起始,字时长,0)字` 正文」的混合格式，
  后端统一解析成 `{t, txt, trans, w[]}`；**翻译与逐字歌词的时间轴经常不一致**（同一首歌两份歌词两套时间），
  因此先判断翻译实际对齐哪一轨，再按文本映射回渲染行，避免译文成片丢失。
- **频谱可视化**：`AnalyserNode` 接在播放链路上，浮点频谱 + 对数分箱 + 频谱倾斜补偿
  （音乐能量天然偏低频，不加补偿就是一条左高右低的斜线）。
- **无 Gradle 构建**：`aapt2 → javac → d8 → zipalign → apksigner` 一条龙，整个 APK 约十几秒。

## 从源码构建

前端（Node + esbuild）：

```bash
cd web
npm install
npm test                # 前端源码回归检查（无测试框架依赖）
npm run build           # 产物输出到 app/src/main/assets/www
npm run preview         # 本地静态预览：http://127.0.0.1:4173/
# 或者：npm run dev  # 一次性构建后启动预览服务器
```

> 本地预览只运行**前端静态文件**，不会自动启动服务端。首次打开可在「设置 → 服务器地址」配置你自己的 CurrentMusic 后端；后端需允许当前网页来源（CORS），或通过同源代理访问。未配置后端时可预览界面，但登录、音源代理、歌单、多人同听等联网功能不可用。
> 前端修订内容和真机/后端待验证项参见 [UI/UX 修订说明](docs/UI_UX_CHANGELOG.md)。

打包 APK（需要 JDK 17 与 Android SDK，build-tools 34）：

```bash
CM_KS_PASS='你的签名库口令' ./build.sh      # 首次会生成自签名 keystore
```

> 本仓库**不包含后端服务**，因此仅凭本仓库无法跑通完整服务；前端产物本身可以在浏览器里打开，
> 但登录、播放等能力依赖后端接口。

## 仓库边界

| | 内容 |
|---|---|
| ✅ 包含 | Android 壳工程（`app/`）、前端源码与构建脚本（`web/`）、构建产物、公开文档 |
| ❌ 不包含 | 后端服务与数据库、签名密钥、任何音源/短信/邮件凭据、APK 产物 |

这样做是为了能公开分享客户端实现，同时不给上游服务与自建后端带来风险。
